# 공통: 제품이 원하는 것과 채점 방식

## 이 제품이 원하는 것 (모든 파트에 깔리는 의도)

- **최종 질문**: "우연한 만남의 설렘은 남기면서, 참가자의 불확실성과 좋은 테이블을 만드는 운영자의 수고를 어떻게 줄일 수 있을까?"
  → 참가자 쪽은 *불확실성 감소*(지금 상태·다음 일·이유가 보임), 운영자 쪽은 *수고 감소*(정상 흐름은 손 안 댐), 그리고 *설렘 유지*(사람 정보는 확정 전엔 감춤, 만남 자체가 주인공).
- **앱의 목적**: "단순히 모임을 보여주거나 참가자를 서로 채팅하게 만드는 것이 아니다." 수작업 흐름 `신청 → 결제 → 자동 매칭 → 자동 재배치 → 자동 확정 → 식당·단체방 안내 → 참석 → 피드백 → 다음 매칭`을 하나로 잇는 것이 핵심.
- **운영 원칙**: 정상 흐름은 운영자 개입 없이 끝난다. 운영자는 결제 오류·식당 부족·해결 안 된 조건 충돌·신고처럼 자동 처리가 불가능한 예외만 본다.
- **완료 조건(온보딩)**: "화면 수보다 end-to-end 시나리오 완주가 우선". 한 회차가 운영자 없이 끝나는지 증명.
- **설명 가능성(온보딩)**: "매칭 결과는 점수보다 설명 가능성이 먼저". 참가자에게 적용 기준·함께 매칭된 이유·확정/재배치/대안 사유·운영자 조정 내용을 보여준다.
- **데이터 루프(온보딩)**: "참가 이력과 피드백이 누적될수록 다음 매칭의 품질이 높아지는 데이터 루프"가 제품의 진짜 자산.
- **반복 참여 설계(온보딩)**: 경험은 한 번의 식사보다 반복 참여(재방문)를 설계한다.
- **신뢰성(온보딩)**: Idempotency(재실행해도 중복 결제·테이블·방·환불 없음), Audit log(상태 변경 시각·주체·원인·이전 값), Retry(푸시·식당·결제 실패는 자동 재시도 후 예외 큐).

## 해커톤 완료 조건 (PRD 18장, 하나의 데모에서 끊김 없이)

1. 서로 다른 프로필의 테스트 참가자들이 날짜·지역을 선택하고 신청한다.
2. 매칭 마감 시각에 시스템이 결제 완료자 대상 자동 매칭을 실행한다.
3. 필수 조건과 우선순위에 따라 4~6인 테이블을 생성한다.
4. 4명 미만·조건 미충족 조합을 해제하고 다른 적합한 테이블로 자동 재배치한다.
5. 검증을 통과한 테이블을 운영자 승인 없이 자동 확정한다.
6. 지역·시간·인원에 맞는 식당을 자동 배정하고 앱 단체방을 자동 생성한다.
7. 참가자가 앱 단체방에서 매칭 결과·식당·큐레이션·행사 안내를 확인한다.
8. 매칭 못 된 참가자에게 다른 일정을 추천하고, 일정 이동 또는 환불 선택이 자동 처리된다.
9. 행사 전 리마인드와 행사 중 대화 콘텐츠가 자동 게시된다.
10. 행사 후 참가자가 체크인과 만족도·사람별 선호를 입력한다.
11. 다음 매칭에서 이전 만남과 피드백이 반영된 것을 확인한다.
12. 정상 시나리오 전체가 운영자 개입 없이 완료되고, 해결 안 된 예외만 운영자 화면에 나타난다.

각 항목이 어느 파트 책임인지는 파트 문서에 적었다.

## 우선순위

P0 필수 / P1 권장 / P2 후속. 해커톤 결과물은 **P0 흐름이 처음부터 끝까지 시연 가능**해야 한다. P0 하나가 빠지면 그 파트는 최대 60%까지만 줄 수 있다.

## 채점 방식 (모든 평가 에이전트 공통)

각 합격 기준을 다음 넷 중 하나로 판정한다.

| 판정 | 뜻 | 점수 |
|---|---|---|
| 통과 | 코드에 있고, 실제로 돌려 보거나 테스트로 확인함 | 1 |
| 부분 | 있으나 일부 상태·예외가 빠졌거나, 화면에서만 보이고 자동으로 안 돎 | 0.5 |
| 실패 | 없거나 동작하지 않음 | 0 |
| 확인 불가 | 실행 환경이 없어 못 봄(이유를 적는다) | 계산에서 제외하되 목록에 남김 |

파트 점수 = (통과 + 0.5×부분) ÷ 판정 가능한 항목 수 × 배점. P0 실패가 있으면 위 상한 적용.

**증거 없이 통과 주지 않는다.** 각 판정에 파일 경로:줄, 테스트 이름, 배포 URL 화면, DB 조회 결과 중 하나를 붙인다.

## 검사 수단

- 코드: 저장소 `src/`, `supabase/migrations/`.
- 단위 테스트: `npm test` (vitest, 매칭 엔진 `src/lib/matching/*.test.ts`).
- 정적 검사: `npx tsc --noEmit`, `npm run lint`.
- 배포본: https://wooyeon-table-ten.vercel.app (참가자 `/`, 어드민 `/admin`, 심사 안내 `/guide`). 브라우저 자동화(Playwright, `/opt/pw-browsers/chromium`)로 실제 화면을 연다.
- 시연 데이터 초기화(`/admin`의 심사용 시연 패널)는 **데이터를 지우는 작업**이라 사용자 허락 없이 누르지 않는다.
- 비밀번호·키는 화면에 입력하지 않는다. 테스트 계정이 필요하면 `/guide`에 공개된 것만 쓴다.
