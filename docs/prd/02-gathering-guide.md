# 파트 2. 모임 안내 (20점)

심사기준: "식당 배정부터 모임 안내까지 자동 처리 구현 정도"
PRD: 8장 INF-01~08, 9장 CON-01~04, 14장 알림 시나리오, 15장 식당 배정 실패, 16장 메시지 발송 기록
완료 조건 책임: 6, 7, 9

## PRD가 원하는 것

- 지금은 "행사 2일 전 카카오톡 단체방 생성·식당 안내 → 1일 전 리마인드 문자 → 단톡방 대화 콘텐츠"를 운영자가 손으로 한다. 이걸 **확정 순간부터 자동**으로.
- "흩어진 정보를 한곳에서 관리하고 반복 작업을 자동화" (참가자 조합, 결제, 단체방, 큐레이션·리마인드, 식당).
- 단체방은 그냥 채팅방이 아니다. 시간·장소·**테이블 조합 큐레이션**·취소 정책을 시스템이 올리고, 행사 중엔 대화 주제·아이스브레이킹이 자동으로 올라온다.
- 실패는 자동 재시도, 반복 실패만 운영자에게.

## 요구사항

| ID | 우선 | 요구 |
|---|---|---|
| INF-01 | P0 | 자동 확정 즉시 앱 푸시 + 앱 내 알림 |
| INF-02 | P0 | 확정된 지역·시간·인원에 맞는 예약 가능 식당을 파트너 재고에서 자동 배정. 없을 때만 운영자 예외 |
| INF-03 | P0 | 식당명, 주소, 지도 링크, 집합 시간, 예약명, 식사 가격 안내 표시 |
| INF-04 | P0 | 확정과 동시에 앱 내 단체 채팅방 생성, 전원 자동 초대 |
| INF-05 | P0 | 단체방에 시간·장소, 테이블 조합 큐레이션, 취소 정책을 시스템 메시지로 자동 게시 |
| INF-06 | P0 | 매칭 전엔 다른 참가자 개인정보 비공개. 확정 후에도 제한된 소개만 |
| INF-07 | P0 | 행사 1일 전 시간·장소·예약명·취소 정책을 푸시 + 단체방에 자동 안내 |
| INF-08 | P0 | 푸시·시스템 메시지 실패 시 자동 재시도, 반복 실패만 운영자 예외 |
| CON-01 | P0 | 테이블별 대화 주제와 아이스브레이킹 게임 확인 |
| CON-02 | P0 | 공통 관심사·대화 성향 기반 스몰토크 주제 최소 3개 |
| CON-03 | P0 | 행사 시작 시각에 단체방에 대화 주제·아이스브레이킹 자동 게시 |
| CON-04 | P1 | 운영자가 콘텐츠를 미리 등록하고 테이블 유형별 노출 규칙 설정 |

## 알림 시나리오 (14장) — 각 시점에 실제로 발송되는지

신청 완료(내용·수정·취소 방법) / 결제 대기(방법·기한) / 결제 완료(자동 매칭 예정일) / 자동 재배치 중(다른 테이블 찾는 중) / 매칭 확정(날짜·지역·식당·집합 시간·단체방) / 매칭 실패(사유·대체 날짜·지역·보관·환불) / 일정 이동 완료(바뀐 회차·매칭 예정일) / 환불 요청·완료(금액·상태) / 행사 1일 전(시간·장소·예약명·취소·노쇼 정책) / 행사 종료 후(만족도·안전 피드백 요청) / 다음 모집 시작(선호 지역·요일 맞춤 추천).

## 예외 (15장)

- 식당 자동 배정 실패 → 같은 지역 다른 파트너 식당 탐색, 모두 실패할 때만 운영자 예외.

## 합격 기준과 검사 방법

| # | 기준 | 검사 |
|---|---|---|
| G1 | 확정과 같은 트랜잭션/흐름에서 식당 배정·단체방 생성·초대가 일어난다 | `pipeline.ts`/러너, DB 결과 |
| G2 | 식당은 지역·시간·인원·수용 가능 수로 고른다. 같은 지역 다른 식당 재시도 후에만 예외 | 배정 함수 + 테스트 |
| G3 | 참가자 화면에 INF-03 6개 정보가 모두 있다(지도 링크 포함) | 배포본 `/tables/[id]` |
| G4 | 단체방 첫 시스템 메시지에 시간·장소·큐레이션·취소 정책 | 배포본 단체방 |
| G5 | 확정 즉시 푸시 + 앱 내 알림 기록 | `notify.ts`, `push.ts`, notifications 테이블 |
| G6 | 1일 전 리마인드가 스케줄로 푸시·단체방 둘 다 | cron, 템플릿 |
| G7 | 발송 실패 재시도 횟수·이력, 반복 실패만 예외 큐 | `notify.ts`, 예외 테이블 |
| G8 | 대화 주제 ≥3개가 공통 관심사·대화 성향에서 나온다(고정 문구 아님) | `contents.ts`, 테이블별 결과 |
| G9 | 행사 시작 시각에 콘텐츠 자동 게시 | cron + 단체방 메시지 |
| G10 | 14장 알림 11개 시점 각각 템플릿과 발송 지점이 있다 | `templates.ts` grep + 호출 위치 |
| G11 | 매칭 전 다른 참가자 정보 비노출, 확정 후 제한된 소개만 | 배포본 화면 |
| G12 | (P1) 어드민 콘텐츠 등록·노출 규칙이 실제 게시에 반영 | `/admin/contents` → 게시 결과 |

## 흔한 함정

- 단체방이 "채팅만 되는 방"이라 큐레이션·정책 공지가 없음.
- 리마인드가 앱 내 알림에만 있고 단체방에는 안 올라감(둘 다 요구).
- 대화 주제가 모든 테이블에 같은 고정 목록.
- 실제 푸시는 기기 검증 전이라 "확인 불가"로 남는 경우 — 구독 저장·발송 코드·실패 재시도까지는 코드로 확인한다.
