# 결제, 대기자 자동 전환, 운영자 긴급 수정, 대화 콘텐츠

## 결제 (토스페이먼츠)
- 결제 화면에서 토스 결제창(v2, `requestPayment`)을 연다. 카드는 통합결제창, 카카오페이·네이버페이·토스페이는 간편결제 자체창.
- 주문번호 `wt-{payment_id}-{시각}`. 돌아오면 `/api/payments/toss/success`에서 주문번호가 이 결제 건인지, 금액이 서버 기록과 같은지 확인한 뒤 `POST /v1/payments/confirm`으로 승인한다.
- 승인되면 `markPaid`가 결제·이용권·신청 상태를 바꾼다. 대기·실패 상태일 때만 바뀌어서 두 번 돌아와도 한 번만 승인된다.
- 환불은 `refundPayment` 한 곳에서. 토스 결제면 `POST /v1/payments/{paymentKey}/cancel`(멱등 키 `refund-{payment_id}`), 실패하면 `REFUND_FAILED` + 예외 처리함에 올리고 운영자가 "환불 다시 요청"으로 재시도한다.
- 키: `TOSS_CLIENT_KEY`/`TOSS_SECRET_KEY`. 비어 있으면 토스 문서 공개 테스트 키로 동작한다. 사업자 등록 후 라이브 키를 넣으면 시연용 버튼(즉시 결제, 실패 보기)은 사라진다.

## 대기자 자동 전환 (STA-07)
- 확정 테이블에서 취소·제외로 빈자리가 생기면, 같은 회차에서 매칭되지 못한(대안 선택 대기) 사람 중 그 일정을 골랐고 나이·제외 관계가 맞는 사람에게 신청 순서대로 한 명씩 묻는다 (`seat_offers`).
- 응답 기한: 지금부터 6시간, 다만 모임 3시간 전까지. 30분도 안 남으면 묻지 않는다.
- 수락: 조건을 다시 확인하고 테이블에 합류, 결제는 그대로 쓴다. 거절·기한 만료·조건 변경: 다음 대기자. 받을 사람이 없으면 기존 인원 부족 정리(재배치/대안 안내)로 넘어간다.
- 기한 만료는 tick에서 처리한다.

## 운영자 긴급 수정 (MAT-14)
어드민 테이블 상세 → 운영자 긴급 수정. 참가자 이동, 참가자 제외(즉시 환불 선택), 테이블 병합(같은 일정, 최대 인원 이하), 테이블 분리(두 쪽 모두 최소 인원 이상, 새 테이블은 식당 배정·단체방·리마인드 자동), 테이블 해제.
사유 필수, 모든 변경은 `status_events`에 `admin:{id}`와 `[운영자 긴급 수정] 사유`로 남고, 관련 참가자에게 알림과 단체방 공지가 나간다. 나이 차이·차단 관계는 여기서도 완화하지 않는다.

## 대화 콘텐츠 관리 (CON-04)
어드민 → 대화 콘텐츠. 주제·아이스브레이킹 등록·수정·노출 중지, 관심사 태그, 테이블 유형(첫 참가 위주·재방문 위주·4인·5~6인·20대·30대 이상), 우선순위.
노출 규칙(`settings.content.rules`): 주제 개수(3~6), 아이스브레이킹 개수, 관심사 가중치, 유형 가중치. 테이블 상세에서 실제로 나갈 콘텐츠를 미리 볼 수 있다.
