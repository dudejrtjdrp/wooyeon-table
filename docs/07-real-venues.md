# 실제 식당 데이터 (2026-10-20)

시연용 가상 식당을 서울 네 동네(홍대·잠실·강남·을지로) 실제 식당 24곳으로 바꿨다. 운영사 Q&A의 '식당은 평점·예약 가능 여부를 본다'를 실제 값으로 보여 주려는 것이다.

- 원본: `data/real-venues.json`. 식당마다 확인한 출처(`source_urls`, 카카오맵·다이닝코드·캐치테이블)와 평점 출처(`rating_source`)가 들어 있다. DB에는 화면에 쓰는 값만 넣고, 출처는 이 파일로 남긴다.
- 평점은 카카오맵 기준이다(네이버는 조회가 막혀 못 봤다). 4.3 미만 6곳은 업종을 고르게 맞추려고 넣었다. 배정은 원래 규칙대로 4.3 이상을 먼저 고른다.
- 1인 가격대와 테이블당 좌석은 메뉴·방문 후기로 짐작한 값이다(가정).
- 예약은 여전히 모의(mock) 어댑터다. 실제 식당에 예약 요청이 가지 않는다(`src/lib/reservations.ts`).
- 사진은 실제 매장 사진이 아니라 업종에 맞춰 AI로 만든 분위기 사진(`public/venues/ai-*.jpg`)이다. 실제 매장 사진은 저작권이 있어 쓰지 않았다. 참가자·어드민 화면에 'AI로 만든 분위기 사진이에요'가 함께 보인다(`src/lib/venue-photo-kind.ts`).

## 넣는 법
`node --env-file=<환경 파일> scripts/apply-real-venues.mjs [--dry]`

- 같은 동네·같은 이름이 있으면 정보만 맞춘다(배정 켜짐/꺼짐은 운영자가 정한 그대로).
- 없으면 그 동네의 가상 식당을 하나씩 실제 식당으로 고쳐 쓴다. 지난 테이블·예약 기록이 그 식당을 가리키고 있어 지우지 않는다. 그래서 **지난 시연 테이블은 실제로 가지 않은 실제 식당 이름으로 보인다**(시연 데이터라서 받아들인 한계). 무엇을 무엇으로 바꿨는지는 변경 이력(`status_events`, actor `system:real-venues`)에 남는다.
- 남는 가상 식당과 운영 동네 밖 식당은 배정을 끈다(지우지 않음).
- 여러 번 돌려도 결과가 같다. 로컬 시뮬레이션 DB에 먼저 적용했고, 운영 DB는 성효님 확인 뒤 같은 스크립트로 넣는다.
