# 시연용 봇 (심사 시연 전용)

**실제 운영 기능이 아니다.** 심사 때 혼자 신청해도 테이블이 차고, 단체방이 사람 사는 방처럼 보이게 하려고 만든 시연 도구다. **기본은 꺼짐**이다. 시연할 때만 어드민 홈 아래 심사용 시연 패널에서 **시연 봇 → 켜기**(settings `demo.bots` = `{ on: true }`)로 켠다. 켜고 끈 기록은 변경 이력에 남는다. 꺼져 있으면 아래 일이 하나도 일어나지 않는다.

**실제 회원과 섞이지 않게 막는 장치**
- 봇은 시연 계정(`users.is_demo = true`)이 결제했을 때만 같이 신청한다. 실제 회원(`is_demo = false`)이 결제하면 켜져 있어도 봇이 붙지 않는다.
- 같은 결제 완료 알림이 두 번 와도 한 번만 붙는다(settings `bots-join:<신청 id>`를 먼저 잡는다).
- 운영 지표는 '시연 데이터 빼기'를 고르면 시연 계정의 신청·후기·예외를 빼고 센다. 결제 화면의 결제 완료 금액에는 시연 계정 모의 결제가 얼마 들어 있는지 따로 적는다.
- 아래 숫자(노쇼 비율, 후기 점수 성향, 나이 ±3살 등)는 모두 **시연용 가정**이다. 실제 운영 데이터에서 나온 값이 아니다. 외부 AI API는 쓰지 않고, 성격별 대본에서 고른다.

코드: `src/lib/sim/` (persona·scripts·plan·join은 DB 없는 계산, bots.ts가 DB에 쓴다). 테스트 `src/lib/sim/sim.test.ts`.

## 누가 봇인가
- `users.is_demo = true`이면서 `login_id`가 `test-`로 시작하는 계정. 시연 패널 '테스트 참가자 만들기'로 만든 사람과 봇이 같이 신청할 때 새로 만드는 사람(`test-bot-…`)이 여기에 든다.
- 시연 참가자 계정(`010…`, 예: 강우진 01091000000, 김우연)은 `is_demo`여도 **사람**으로 본다. 봇이 이 사람들 말에 답하고, 대신 체크인·후기를 하지 않는다.
- 봇은 봇 말에 답하지 않는다(끝없이 서로 말하는 일 방지). 정해진 질문·답 한 쌍(하루 전)만 대본으로 둔다.

## 성격 (persona.ts)
user id 해시와 프로필로만 정해서 언제 계산해도 같다.
- 말투: MBTI E/I와 본인 성향(유쾌한·에너지 넘치는·리액션 좋은·호기심 많은 ↔ 차분한·진지한)으로 `말 많음 / 예의 바름 / 짧게`.
- 웃음: 말 많거나 유쾌한 사람은 가끔 문장 끝에 'ㅎㅎ'(한 메시지에 한 번까지). 이모지는 안 쓴다.
- 도착 습관: 일찍(15~7분 전) / 제때(5분 전~2분 뒤) / 조금 늦게(6~15분). 차분한 사람은 일찍 오는 쪽.
- 후기 성향(warmth): 다정한·리액션 좋은 사람은 후하고, 솔직한·진지한 사람은 깐깐하다.

## 언제 무슨 말을 하나 (plan.ts)
메시지마다 `dedupe_key = bot:<테이블>:<사람>:<단계>:<번호>`라 몇 번 돌아도 한 번만 올라간다.

| 단계 | 기준 시각 | 내용 |
|---|---|---|
| 인사 | 확정 공지가 올라온 실제 시각 + 20초~2분 간격 | 한 명씩 자기소개(직업·관심사), 말 많은 사람은 한 마디 더 |
| 하루 전 | 시작 24시간 전 + 1시간 안 (시연 시계) | 도착 계획, 식당·업종 얘기, 질문 하나와 다른 봇의 답 |
| 모임 시작 | 시작 시각 전후 (시연 시계) | 일찍 온 사람 '자리 잡았어요', 늦는 사람은 미리 알리고 나중에 '도착했어요'. 대화 주제가 올라오면 2~4분 뒤 한 명, 9~20분 뒤 한 명이 번호를 짚어 답한다 |
| 끝난 뒤 | 끝난 시각 바로 + 30분 안 | 두세 명이 끝인사 |

- 단계가 지나면(인사·하루 전은 시작 뒤, 시작은 끝난 뒤, 끝인사는 다음 날) 그 단계 말은 건너뛴다. 봇을 늦게 켜도 지난 얘기를 꺼내지 않는다.
- 같은 테이블에서 같은 문장이 두 번 나오지 않게 고른다. 상황마다 대본이 5개 이상이다.
- 시각 표시는 다른 단체방 메시지와 같은 실제 시각이다. 시연 시계를 크게 옮겨 한꺼번에 올라갈 때는 방의 마지막 메시지와 지금 사이에 순서대로 펼쳐 둔다.

## 사람 말에 답하기
- 사람이 단체방에 쓰면 응답을 보낸 뒤(`after`) 2~3초 간격으로 한두 명이 답한다. 인사·질문이면 두 명, 아니면 대개 한 명. 말 많은 사람이 먼저 나선다.
- 키워드로 뜻을 짐작한다: 인사, 몇 시에 오는지, 늦는다, 메뉴·술, 위치·입구, 고맙다, 도착했다, 그 밖의 질문, 나머지(공감 + 되묻기). 몇 시에 오냐고 물으면 자기 도착 습관대로 시각을 말한다.
- '늦을 것 같아요' 버튼으로 올라간 안내에도 '천천히 오세요'처럼 답한다.
- 서버가 끊겨 못 한 답은 다음 자동 처리(tick)에서 한다(3시간 안 메시지만). 끝난 모임에는 답하지 않는다.
- 단체방을 열어 두면 새 메시지 확인 요청(2.5초마다)에 붙어 10초에 한 번 그 방만 확인해, 차례가 된 말이 한 마디씩 올라온다.

## 같이 신청하기 (join.ts, bots.ts botsJoin)
- 사람이 결제를 마치면(모의 결제·토스·보유 이용권) 그 사람이 고른 첫 일정(가장 이른 날짜, 운영 지역 우선)에 봇을 넣는다.
- 그 일정에 이미 결제하고 기다리는 사람 중 나이 ±3살인 사람을 세고, 사람 포함 **최소 인원 4명**이 되도록 모자란 만큼만 넣는다.
- 아직 그 회차에 신청하지 않은 봇을 먼저 쓴다: 나이 ±3살, 관심사 1~2개 겹침, 성비가 맞는 순. 모자라면 새로 만든다(나이 ±3, 관심사 1~2개 겹침, 성별은 성비에 맞게, 가격대는 사람과 같게).
- 신청 모양은 시연 패널 테스트 참가자와 같다: 1회권 결제 완료(PAID), 그 일정 하나만(`near_ok=false`), `status_events`에 `system:demo-bot`으로 한 줄.
- 그다음은 원래 흐름 그대로다: 자동 매칭 → 확정 → 식당 배정 → 예약(모의 어댑터) → 단체방 첫 공지. 매칭 엔진·식당 고르기·대화 주제 고르기는 봇 때문에 바뀌지 않는다.

## 모임 날
- 체크인: 각자 도착 시각이 지나면 앱 체크인과 같은 길로 `attendance_status = ATTENDED`, `checked_in_at`, `status_events`(actor `system:demo-bot`). 모임 종료 처리보다 먼저 돌아서 온 봇이 노쇼 후보로 잘못 올라가지 않는다.
- 노쇼: 봇이 둘 이상인 테이블 셋 중 둘꼴로 한 명은 오지 않는다(체크인·도착·끝인사 없음). 모임이 끝나면 원래 규칙대로 노쇼 후보 예외로 올라가 운영자가 확인한다.
- 후기: 끝난 뒤 체크인한 봇이 `feedbacks`에 점수 5개와 한 줄 소감을 남긴다(후한 사람 4~5점, 깐깐한 사람 3~4점 쪽). 기분이 좋았던 봇은 가끔 사람에게 '또 만나고 싶어요'(`person_prefs = again`)를 남긴다. `status_events`에 feedback SUBMITTED.

## 가정
- 봇 계정 비밀번호는 테스트 참가자와 같은 `demo1234`다. 시연 페이지에서 들어가 볼 수 있다.
- 봇 메시지는 다른 참가자에게 푸시를 보내지 않는다(알림이 시끄러워지지 않게).
