# 파트 7. 프로젝트 기록 (10점)

심사기준: "Blaybus Workspace 계획 및 진행 기록의 충실도"
출처: 킥오프 슬라이드(Workspace 구조, 대시보드, 리마인드, 제출 가이드)

## 심사가 원하는 것

- Workspace 구조대로 계획: **프로젝트 목표 → 아젠다(마일스톤, Depth 1) → 워크(중간 산출물, 담당자·목표 일정, Depth 2) → 태스크(최소 단위 행동, 담당자·투입 시간, Depth 3)**.
- "단순 결과물이 아닌 기획부터 실행까지 모든 과정을 구조적으로 기록" → "기록된 활동을 수치화된 데이터로".
- 대시보드가 집계하는 것: 주간 워크 완료율, 투입 시간, 아젠다별 투입 시간, 태스크 vs 미팅 비중, 병목.
- 제출(10.21 수 23:59): Output 탭 제출 메시지에 참가자용·운영자용 배포 링크와 테스트 계정. **제출은 사용자가 직접 지시할 때만.**

## 합격 기준과 검사 방법

| # | 기준 | 검사 |
|---|---|---|
| R1 | 아젠다가 PRD 파트(매칭·안내·피드백·어드민·참가자 앱·설계/배포)와 대응한다 | Blaybus Workspace |
| R2 | 모든 워크에 담당자·목표일이 있다 | Workspace 목록 |
| R3 | 실제로 한 작업마다 태스크가 있고, 투입 시간이 **실제 타이머**로 쌓였다(지어낸 시간 없음) | 태스크 투입 시간 |
| R4 | 끝난 태스크는 완료 처리, 진행 중은 진행 중 — 상태가 실제와 맞다 | Workspace |
| R5 | 방향 전환·결정 이유가 태스크 설명이나 기록에 남는다(예: 디자인 방향 변경, 지역 선택 방식) | 태스크 상세 |
| R6 | 매일 기록이 있다(10.15~10.21 하루도 빈 날 없음) | 날짜별 |
| R7 | 아젠다별 투입 시간 분포가 심사 배점과 크게 어긋나지 않는다(자동 매칭·안내에 충분한 시간) | 대시보드 |
| R8 | 저장소 커밋 메시지·docs와 Blaybus 기록이 서로 맞는다 | git log 대조 |
| R9 | 제출 체크리스트(링크 2개·테스트 계정)가 준비돼 있다 — **제출 버튼은 누르지 않는다** | 메모 |

## 평가 에이전트 주의

- Blaybus 화면은 브라우저로 읽기만 한다. 태스크 추가·타이머 조작은 평가가 아니라 작업이므로 평가 중에는 하지 않는다.
- 어떤 경우에도 Output 탭 제출을 누르지 않는다.
