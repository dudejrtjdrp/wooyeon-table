# 파트 4. 운영자 어드민 (10점)

심사기준: "**예외 처리 중심** 운영자 화면의 완성도"
PRD: 4장 운영자 권한, 5장 운영자 흐름, 11장 운영자 웹 어드민, MAT-13·14·15, SAF-02, CON-04, 15장 예외, 16장 개인정보·운영 및 추적, 17장 운영자 웹 화면 목록
완료 조건 책임: 12

## PRD가 원하는 것

- "운영자는 모든 테이블을 일일이 검수하지 않는다." 자동 처리 불가 예외만 본다 → 어드민의 첫 화면은 **처리할 예외**가 주인공. 정상 건은 숫자로 요약.
- 운영자 문제: Google Forms·입금 문자·카톡방·식당 예약을 수기로 → 한곳에서.
- "CS를 자동화하고 싶다" → 대기·실패·환불 상태를 운영자가 일일이 설명하지 않아도 되게.
- 목표 지표: 자동 확정률↑, 운영자 개입률↓, 처리 시간↓ (온보딩).
- 운영자 계정 권한별 접근 통제와 주요 변경 이력.

## 필수 화면 (11장)

운영 대시보드 / 회차 관리 / 신청자 목록 / 자동 매칭 모니터 / 예외 처리함 / 테이블 상세 / 결제·환불 / 참석 관리 / 피드백·안전 / 자동 메시지 관리 / 식당 재고 관리.

17장 운영자 웹 목록: 대시보드, 회차 생성·관리, 식당 재고·자동화 규칙, 신청자·결제·자동 환불 목록, 자동 매칭·재배치·확정 모니터, 예외 처리함, 테이블·식당·단체방 조회, 자동 안내·리마인드 이력, 참석·취소·노쇼, 피드백·신고.

## 대시보드에 바로 보여야 하는 9가지

전체 신청자·결제 완료자 수 / 자동 매칭·재배치·확정 성공 건수와 성공률 / 대체 일정·환불 선택 대기 수 / 자동 해결 안 된 조건 충돌 / 배정 가능 식당 없는 테이블 / 안내·리마인드 발송 실패 / 자동 환불 실패 / 당일 취소·노쇼 후보 / 미처리 신고.

## 사용 편의 점검 (성효님 지시, 2026-10-16)

운영자도 사용자다. "운영자는 예외만 처리"가 실제로 쉬운지 본다. 점수에 넣는다.

| # | 기준 | 검사 |
|---|---|---|
| E1 | 예외 하나를 처리하는 데 필요한 정보(누구·무엇·왜·추천 조치)가 한 화면에 있고, 클릭 3번 안에 끝난다 | 배포본 예외 처리함 |
| E2 | 대시보드 첫 화면에서 "지금 처리할 일"이 숫자·링크로 먼저 보이고, 0건이면 0건이라고 분명히 말한다 | 배포본 |
| E3 | 되돌릴 수 없는 동작(환불·제한·긴급 수정·초기화)은 확인을 한 번 더 받고, 결과를 화면에 알려 준다 | 배포본 + 코드 |
| E4 | 처음 온 운영자가 설명 없이 회차 만들기→결과 확인까지 간다(빈 화면·필드 안내 포함) | 배포본 |

## 흔한 함정

- 대시보드가 예쁜 KPI 카드 위주이고 "지금 처리할 일"이 뒤로 밀림.
- 예외를 해결해도 상태만 바뀌고 이력이 없음.
- 시연 패널이 실제 운영 화면처럼 보여 심사자가 헷갈림 — 시연 도구는 분리 표시.
