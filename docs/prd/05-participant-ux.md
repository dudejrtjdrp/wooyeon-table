# 파트 5. 참가자 경험 (10점)

심사기준: "모바일 참가자 앱의 사용 편의성"
PRD: Part1 '해결할 문제 2(신청 후 이탈 감소)', 2장 참가자 문제, 3장 제품 목표 1·4, 4장 참가자 권한, 5장 참가자 흐름, 6.1 ACC, 6.2 APP·PAY, 6.3 STA, 12장 상태값, 16장 사용성, 17장 참가자 화면 목록

## PRD가 원하는 것

- **불확실성 감소**: "신청, 결제, 매칭 대기, 재배치, 확정 상태를 명확히 보여주고, 매칭 실패 시 대체 날짜·지역을 안내."
- 참가자 문제 그대로 해결: 상태를 실시간으로 모름 / 환불하려면 운영자에게 계좌를 문자로 보냄 / 매칭 실패 시 다시 신청이 번거로움.
- **사용성 4원칙(16장)**: 모바일 우선 / 최초 신청은 프로필 포함 **5분 안** / **홈에서 현재 신청·결제·매칭 상태를 바로** / **실패·대기 상태에서도 다음 행동을 한 화면 안에서** 선택.
- **설렘 유지**(최종 질문): 확정 전엔 사람 정보를 감추고, 만남 자체를 기대하게.
- 설명 가능성: 참가자에게 적용 기준·함께 매칭된 이유·확정/재배치/대안 사유·운영자 조정 내용을 보여준다(온보딩).
- PRD는 **시각 스타일(색·브랜드 톤)을 정하지 않았다.** 디자인 평가는 위 사용성 원칙과 흐름 완주로 한다.

## 참가자 흐름 (5장) — 끊김 없이 이어지는지

1 로그인·회원가입 → 2 기본 프로필·매칭 선호 테스트 → 3 날짜·지역 선택 → 4 이용권 선택·결제 → 5 매칭 대기 확인 → 6 확정 후 테이블·식당·단체방 → 7 행사 전 리마인드 → 8 식사·단톡방 콘텐츠 → 9 만족도·안전 피드백 → 10 다음 일정 추천·재신청.

## 참가자 화면 목록 (17장)

로그인·회원가입 / 프로필·매칭 선호 테스트 / 모집 일정·지역 선택 / 이용권·결제 / 신청 완료 및 자동 매칭·재배치 상태 / 매칭 실패 해결(대체 일정·보관·환불) / 매칭 확정 상세(날짜·식당·단체방) / 단체방·대화 주제·아이스브레이킹 / 체크인·만족도·사람별 선호·신고 / 참가 이력·다음 일정 추천.

## 디자인 시안 평가에 쓸 때

시안(캔버스)만 볼 때는 U3·U4·U5·U7·U10·U11·U12·U16과 "흐름 1~10이 화면으로 이어지는가"를 본다. 색·브랜드 취향은 점수에 넣지 않고 의견으로만 적는다.

## 흔한 함정

- 홈이 "새 일정 홍보" 위주라 내 신청 상태가 아래로 밀림(지난 감사에서 실제로 발생: 결제 대기 신청이 있는데 '새 식탁' 히어로가 뜸).
- 실패 화면에 설명만 있고 버튼이 다른 화면에 있음.
- 상태 이름이 화면마다 다름(예: '대기'·'기다리는 중'·'매칭 전').
