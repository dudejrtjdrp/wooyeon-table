# 운영사 Q&A 답변 (2026-10-16, Blaybus 공지)

PRD에 없던 값 중 **운영사가 답을 준 것**은 이제 PRD와 같은 근거로 본다. 평가 에이전트는 이 문서도 함께 읽고, 아래 'Q 확인 항목'을 자기 파트 합격 기준에 더해 채점한다.
"직접 정하세요"라고 답한 항목은 성효님이 정한 값을 따른다. 아직 안 정했으면 '정할 것'으로 남기고 점수에 넣지 않는다.

## 확정된 값 (그대로 따른다)

| 주제 | 운영사 답 |
|---|---|
| 앱 형태 | 설치형 앱이 아니라 **웹앱**. 모바일 웹브라우저에서 링크로 접속. 심사는 제출한 배포 링크로 |
| 환불 불가 시점 | 현재 **화요일 자정(24:00) 이후 환불 불가**. 매칭 마감을 이 시점과 같게 둘지는 우리가 정함 |
| 1회권 | **9,900원** |
| 멤버십 | **1개월 35,000원 / 3개월 75,000원 / 6개월 120,000원** |
| 멤버십 횟수 | 기간 안에 **횟수 제한 없이** 참여 |
| 멤버십 매칭 실패 | **실패한 횟수만큼 이용 기한 연장** |
| 운영 지역 | 지금은 **서울 4곳(홍대·잠실·강남·을지로)**. 초반엔 서울에 집중하고 서울 밖은 나중에 운영. 앱에 넣을지는 우리 판단 |
| 식당 확보 기준 | **리뷰 평점이 좋고 예약이 가능한 곳** |
| 운영자 사전 검토 | **넣지 않는다.** PRD대로 검토 없이 자동 확정 |
| 로고 | 원본 없음. 비슷하게 재현해 써도 됨 |
| 문의·운영 로그 | 제공 안 함 |

## 우리가 정한 것 (운영사: "PRD 원칙 안에서 직접 정하세요" → 성효님 승인 2026-10-16)

| 주제 | 정한 값 | 코드 |
|---|---|---|
| 매칭 마감 = 환불 마감 | 모임 주 화요일 24:00. 결과를 보고 환불하는 일을 막는다. 금·토 모임이면 수요일 아침에 결과 | `lib/policy.ts`, 회차 만들기 기본값 |
| 당일 취소 | 앱에서 막는다. 단체방 '늦을 것 같아요' 버튼, 연락 없이 안 오면 노쇼. 이유: 당일 빠지면 테이블이 4명 아래로 떨어져도 채울 시간이 없고, 남은 사람의 저녁이 깨진다 | `cancelRule`, `lateNotice` |
| 노쇼 | 운영자 확정 → 최근 90일 1회 경고 / 2회 30일 신청 제한(자동) / 3회 운영자 영구 제한 검토. 1회권 환불 없음, 멤버십은 그 회차를 쓴 것으로 보고 연장 없음. 소명하면 운영자가 해제. 이유: 노쇼는 같은 테이블 사람 모두의 경험을 깎는다. 한 번은 실수로 보고 알려 주기만, 반복되면 자동으로 막아 운영자 손을 덜고, 영구 제한처럼 무거운 조치만 사람이 본다 | `lib/noshow.ts` |
| 확정 후 3명 남음 | 필수 조건은 낮추지 않음. 대기자 충원 → 같은 날 다른 테이블 → 매칭 실패 화면(참가자가 선택). 이유: PRD 원칙(필수 조건 완화 금지, 이동·환불은 참가자 선택)을 그대로 지키면서, 운영자 없이 끝나게 하려고 | `attendance.ts`, `resolve.ts` |
| 성비 | 웬만하면 맞춘다: 4명 2:2, 5명 3:2, 6명 3:3·4:2. 한 성별만·한 명만 다른 성별은 다른 조합이 없을 때만, 그때는 매칭 이유에 적는다. 최소 점수 판정에서는 성비 감점을 빼서 성비만으로 테이블이 막히진 않는다 | `score.ts genderBalance` |
| MBTI | E/I가 섞이면 가점, N/S가 같으면 가점, '잘 모르겠어요'는 중간. 이유: 처음 보는 사람끼리는 말하는 사람과 듣는 사람이 섞여야 대화가 끊기지 않고, 관심 주제의 결(N/S)이 비슷해야 이야기가 이어진다 | `score.ts mbtiPair` |
| 멤버십 실패 연장 | 1회당 7일 (모임이 주 1회) | `billing.ts extendMembershipFor` |
| 운영 지역 밖 | 신청 대신 '열리면 알려 주세요'(동네 고르기·직접 적기). 회차를 열면 기다린 사람에게 자동 알림. 어드민 '지역 수요' | `/wish`, `/admin/demand` |
| 식당 예약 | 확정 → 평점 4.3 이상·예약 채널 있는 식당 우선 배정 → 네이버 예약/캐치테이블 어댑터로 예약 요청(지금은 모의, 공개 API 없음) → 10분 간격 재시도, 3번 실패면 예외 큐 → 운영자가 예약 페이지 열고 직접 예약 표시 | `lib/reservations.ts` |

## 반영 상태 (2026-10-16)

가격·멤버십, 마감·환불, 기본 지역·수요 조사, 성비, 식당 평점·예약, 노쇼 단계 제한을 모두 반영했다(마이그레이션 0010). 남은 것: 실제 네이버 예약·캐치테이블 제휴 키를 받으면 `adapterFor`의 live 어댑터 채우기.

추가 반영 (2026-10-16 오후): 시드(`0002_seed.sql`)의 지역을 서울 4곳 묶음(홍대·합정·연남 / 잠실·송파 / 강남·역삼·선릉 / 을지로·종로·광화문)으로 맞추고 PRD에 없는 숫자에 '시연용 가정'을 달았다. 식당 예약이 끝내 안 되면 같은 동네 다른 식당으로 자동으로 바꾸고, 자동 예약 채널 가점은 네이버 예약·캐치테이블에만 준다(`lib/venue-pick.ts`). 확정 후 3명 남음의 판단을 순수 함수로 빼서 테스트했다(`lib/reflow-rules.ts`).
