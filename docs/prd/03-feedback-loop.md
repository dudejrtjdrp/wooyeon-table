# 파트 3. 피드백 반영 (15점)

심사기준: "피드백 수집과 다음 매칭 반영의 완성도"
PRD: Part1 '해결할 문제 4·5', 10장 FDB/SAF/RET, MAT-05·06·16, 15장 안전 신고·피드백 미응답, 16장 개인정보
완료 조건 책임: 10, 11 (+12 일부)

## PRD가 원하는 것

- "테이블·대화·식당 만족도, 재참여 의향, 다시 만나고 싶은 사람과 피하고 싶은 사람을 **안전하게** 수집해 다음 매칭에 반영."
- "**많이 참여한 사람일수록 매칭 알고리즘이 정교해져야** 한다." — 피드백이 저장만 되면 안 되고, 다음 매칭 결과가 실제로 달라져야 한다.
- "이전 참가 결과를 반영한 다음 일정과 새로운 테이블을 제안해 한 번의 식사를 반복 참여로 연결."
- 온보딩: "참가 이력과 피드백이 누적될수록 다음 매칭 품질이 높아지는 데이터 루프"가 제품의 진짜 자산.
- 사람별 선호·신고는 상대에게 절대 보이지 않는다.

## 요구사항

| ID | 우선 | 요구 |
|---|---|---|
| FDB-01 | P0 | 앱 체크인 → 참석 완료. 종료 시각까지 체크인 없으면 노쇼 **후보**, 운영자는 후보만 확인 |
| FDB-02 | P0 | 테이블 분위기·대화·식당 각각 평가 |
| FDB-03 | P0 | 재참여 의향·추천 의향 |
| FDB-04 | P0 | 다시 만나고 싶은/싶지 않은 사람을 비공개로 선택 |
| SAF-01 | P0 | 신고·차단. 신고 내용은 상대에게 비공개 |
| SAF-02 | P0 | 운영자가 신고 검토, 경고·참가 제한·영구 제한 기록 |
| RET-01 | P0 | 과거 참가 날짜·지역, 피드백 제출 여부 확인 |
| RET-02 | P0 | 이전 지역·날짜 선호와 참가 결과로 다음 모집 일정 제안 |
| RET-03 | P1 | 보유 이용권 남은 횟수·유효기간 확인, 다음 신청에 사용 |
| MAT-05 | P0 | 비선호·차단·신고 관계는 같은 테이블 제외 |
| MAT-06 | P0 | 이전에 만난 사람보다 새 사람 우선 |
| MAT-16 | P2 | 누적 참석·만족도·재방문으로 가중치 자동 조정 |

## 예외 (15장)

- 안전 신고 발생 → 피신고자와 신고자를 향후 매칭에서 **즉시** 분리, 운영자 검토 목록.
- 피드백 미응답 → 1회 리마인드, 다음 신청은 막지 않음.
- 당일 취소·노쇼 → 참석 상태와 이용 제한 검토 대상으로 기록.

## 합격 기준과 검사 방법

| # | 기준 | 검사 |
|---|---|---|
| F1 | 체크인이 참석 상태(ATTENDED)를 바꾼다. 미체크인은 노쇼 후보로만 표시 | 코드 + 어드민 참석 관리 |
| F2 | 만족도 3종 + 재참여·추천 의향 입력 화면과 저장 | 배포본 피드백 화면, DB |
| F3 | 사람별 선호(좋음/비선호)가 비공개로 저장, 상대 화면 어디에도 안 보임 | 코드 + 화면 |
| F4 | 비선호·차단·신고 관계가 **다음 매칭 엔진 입력**으로 들어가 같은 테이블 제외 | 엔진 입력 로딩 코드 + 테스트 |
| F5 | 이전 만남 이력이 엔진에 들어가 새 사람 우선 점수에 반영 | `score.ts` + 테스트 |
| F6 | 신고 즉시 양쪽 분리(다음 매칭부터), 운영자 검토 목록에 올라감 | 코드 경로 |
| F7 | 운영자 조치(경고·제한·영구 제한)가 기록되고 제한 상태가 신청/매칭을 실제로 막는다 | 어드민 + 신청 가드 |
| F8 | 참가 이력 화면(날짜·지역·피드백 여부) | 배포본 `/my-tables` 등 |
| F9 | 다음 일정 추천이 과거 선호 지역·요일·참가 결과를 근거로 고른다(그냥 최신 회차 아님) | 추천 로직 |
| F10 | 피드백 미응답 1회 리마인드, 신청은 막지 않음 | cron/템플릿 |
| F11 | "참여가 쌓일수록 정교해짐"을 보여 주는 장치(참석 횟수에 따른 신뢰도·가중, 만족도 반영 등) | 엔진/점수 코드 — 없으면 부분 |
| F12 | (P1) 이용권 남은 횟수·유효기간 표시, 다음 신청에 차감 | 화면 + DB |
| F13 | (P2) 가중치 자동 조정 | 있으면 가산 |
| F14 | 완료 조건 11: 같은 사람 둘이 이전에 만났거나 비선호를 남긴 경우, 다음 매칭에서 실제로 떨어지는 것을 재현 가능 | 시뮬레이션 테스트 |

## 흔한 함정

- 피드백은 저장되는데 엔진이 안 읽음(가장 흔함, F4·F5·F14로 잡는다).
- 신고가 "운영자 승인 후" 분리됨 — PRD는 **즉시** 분리.
- 추천이 "다음 회차 아무거나".
